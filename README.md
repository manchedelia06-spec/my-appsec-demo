# AppSec Pipeline Demo

[![Security Scan](https://github.com/manchedelia06-spec/my-appsec-demo/actions/workflows/security.yml/badge.svg)](https://github.com/manchedelia06-spec/my-appsec-demo/actions/workflows/security.yml)

## О проекте
CI/CD пайплайн с инструментами безопасности для статического анализа (Semgrep), поиска секретов (Gitleaks) и SCA (Trivy).

## Пользовательские правила Semgrep

В этом проекте реализованы **собственные правила статического анализа** для раннего обнаружения небезопасных конструкций в коде на C/C++. Это позволяет блокировать уязвимости на этапе CI/CD, не дожидаясь попадания в production.

### Файл с правилами

Все пользовательские правила находятся в файле:
[`custom-rules/my-insecure-functions.yml`](https://github.com/manchedelia06-spec/my-appsec-demo/blob/main/custom-rules/my-insecure-functions.yml)

### Список детектируемых опасных функций

| Функция | Описание уязвимости | Рекомендация по исправлению |
|---------|---------------------|------------------------------|
| `strcpy` | Копирование строки без проверки длины → buffer overflow | Использовать `strncpy` или `std::string` |
| `gets` | Никогда не проверяет размер буфера → классическая уязвимость | Использовать `fgets()` |
| `sprintf` | Форматирование строки без проверки размера → переполнение | Использовать `snprintf()` |
| `scanf` с `%s` | Чтение строки без ограничения длины → переполнение | Использовать `fgets()` или `%10s` |

### Как это работает

1. При каждом `git push` GitHub Actions запускает Semgrep.
2. Semgrep применяет все правила из папки `custom-rules/`.
3. Если код содержит вызовы перечисленных функций, пайплайн **падает**, что предотвращает попадание уязвимостей в основную ветку.

### Расширяемость

Новые правила легко добавить — достаточно создать YAML-блок в том же файле или добавить новый файл в папку `custom-rules/`. Такой подход позволяет команде безопасности быстро адаптироваться под новые типы атак.

## Уязвимости, которые находит пайплайн
1. Buffer overflow - в vulnerable.c используется `strcpy` без проверки границ и другие функции
2. Hardcoded secrets в secrets.txt — API ключи и пароли в `secrets.txt`
3. Устаревшие зависимости в requirements.txt — Flask 2.0.1 имеет известные CVE
